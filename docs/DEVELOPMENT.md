# 开发指南

## 1. 开发原则

- 领域逻辑不得依赖桌面 UI。
- Windows 与 macOS 只维护一个主干和一套产品源码；禁止复制功能目录形成平台分叉。
- 平台差异只能进入 `PlatformAdapter`、Tauri 原生命令或平台构建配置。
- 对外部模型、OCR、解析器和数据库使用适配器。
- API 契约优先，前后端共享生成的类型定义。
- 所有索引任务必须可观测、可取消、可重试和幂等。
- 新的检索策略必须附带离线评测结果。

## 2. 计划目录

```text
apps/desktop/                   Tauri 2 与原生能力
apps/web/                       React 用户界面
services/knowledge-api/
├─ app/api/                     HTTP 与流式接口
├─ app/domain/                  领域模型和服务
├─ app/ingestion/               解析、OCR、切分和索引
├─ app/retrieval/               召回、融合、重排和上下文
├─ app/providers/               模型、存储和 OCR 适配器
├─ app/infrastructure/          数据库、日志、任务系统
└─ tests/
packages/shared/                OpenAPI 生成类型与事件协议
tests/evaluation/               固定语料、问题、答案和引用标注
```

## 3. 开发环境目标

正式脚手架建立后，应提供统一命令完成：

- 依赖安装
- 数据库迁移
- 本地 API 与前端联调
- 单元和集成测试
- 检索评测
- Windows 与 macOS 打包

开发者不应手工复制模型到源码目录。模型资源通过受版本控制的清单下载或由用户在应用内配置。

## 4. 分支与提交

- 主分支始终保持可构建。
- 功能分支保持短生命周期。
- 提交信息建议使用 Conventional Commits。
- 数据库迁移、API 契约和索引格式变化需要在合并请求中显式说明。
- 不提交真实文档、账号、token、API Key、生产日志和企业测试数据。

## 5. 测试策略

### 5.1 单元测试

- 文本清洗和切分边界
- 权限过滤器
- 融合排序算法
- 引用编号与校验
- 状态机和错误映射

### 5.2 集成测试

- 各格式文档端到端导入
- 任务失败、重试和恢复
- 文档删除后的索引一致性
- 模型 Provider 的超时和取消
- API 鉴权和跨租户访问阻断

### 5.3 评测测试

- 固定知识库和标注问题
- Recall@K、MRR、nDCG
- 引用正确率和答案一致性
- 无答案与无权限问题的拒答率

### 5.4 跨平台测试

- Windows 路径、长路径和文件锁
- macOS 权限、签名环境和 Apple Silicon
- 中英文文件名、Unicode、大小写敏感差异
- 睡眠、休眠、应用异常退出和升级恢复

持续集成必须同时包含 Windows 与 macOS 构建任务。任何影响桌面端、本地 API、文档路径、sidecar 或打包的改动，只有在两个平台均通过后才能合并。若暂时无法在某平台自动验证，必须记录明确阻塞，不得以“后续适配”视为完成。

## 6. 代码质量

- Python 使用类型检查、格式化与静态分析。
- TypeScript 开启严格模式。
- Rust 代码通过格式化、Clippy 和测试。
- 公共接口需要文档字符串和稳定错误码。
- 日志字段使用统一规范并自动脱敏。

## 7. Definition of Done

功能完成至少满足：

- 需求和异常路径明确
- API 和数据迁移已更新
- 单元及必要集成测试通过
- 不降低固定评测集指标，或已说明可接受原因
- Windows 与 macOS 相关影响已评估
- Windows 与 macOS 构建及适用测试均已通过
- 安全、日志、权限和隐私经过检查
- 用户文档和变更记录已更新
