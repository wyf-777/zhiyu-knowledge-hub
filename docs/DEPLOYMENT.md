# 部署与发布

## 1. 发布产物

同一代码库分别构建不同平台安装包：

- Windows x64：NSIS 安装包或 MSIX
- macOS arm64：Apple Silicon DMG/PKG
- macOS x86_64：根据用户需求决定是否支持
- macOS Universal：在分发体积与兼容需求之间评估

“跨平台”表示功能、数据与协议一致，不表示一个安装文件通用于两个操作系统。

## 2. Sidecar 打包

FastAPI 服务需要构建为用户无需安装 Python 的 sidecar。每个平台单独构建、测试和签名，并满足：

- 可从桌面壳获得受控配置
- 动态选择可用环回端口
- 输出结构化启动状态
- 响应优雅退出信号
- 异常退出后由桌面壳提示并支持重启
- 不将临时认证令牌写入日志

## 3. 模型分发策略

不建议把大型模型直接放入桌面安装包。推荐：

1. 安装包只包含应用与必要的小型运行组件。
2. 首次启动检测本地 Ollama/llama.cpp。
3. 用户选择模型后显示体积、许可证和硬件要求。
4. 使用可恢复下载，并校验哈希。
5. 模型保存在应用数据目录或用户指定目录。

Embedding 和 Reranker 也需要版本清单、哈希和许可证信息。

## 4. Windows 注意事项

- 检测或引导安装 WebView2 Runtime。
- 处理长路径、杀毒软件扫描和文件锁。
- 使用代码签名证书签署 EXE、DLL 和安装包。
- 默认数据目录使用 `%LOCALAPPDATA%`，不要写入安装目录。
- 自动更新前确认后台索引任务已安全暂停。

## 5. macOS 注意事项

- 使用系统 WKWebView。
- 使用 Developer ID Application/Installer 完成签名。
- 提交 Apple 公证并 stapling 到发布物。
- 配置 Hardened Runtime 和最小权限 entitlement。
- 处理用户选择目录的安全作用域书签与访问授权。
- 验证 Apple Silicon 原生依赖，避免静默转用不兼容架构。

## 6. 企业部署

企业版建议使用容器化服务：

```text
Gateway / Ingress
├─ Knowledge API
├─ Worker
├─ PostgreSQL
├─ Qdrant
├─ Object Storage
└─ Model Gateway
```

生产环境要求：

- TLS 与企业身份认证
- 数据库、对象存储和向量库备份
- 租户隔离和权限回归测试
- 模型请求审计与敏感信息策略
- 资源限额、队列背压和容量监控
- 明确的升级、回滚和灾难恢复流程

## 7. 自动更新

- 更新清单和安装包必须签名。
- 更新前检查数据库和索引格式兼容性。
- 数据库迁移前创建可恢复备份。
- 不在索引写入关键阶段强制退出。
- 支持暂停自动更新和企业管理员控制发布通道。

## 8. 发布检查清单

- 单元、集成、评测与端到端测试通过
- Windows 与 macOS 干净环境安装验证
- 应用、sidecar 和安装包完成签名
- macOS 公证成功
- SBOM、第三方许可证和模型许可证齐全
- 更新包哈希和签名验证通过
- 新版本迁移及回滚演练完成
- README、变更记录和隐私说明已更新
